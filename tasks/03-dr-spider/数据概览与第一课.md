## 第一课 · 从一张表理解查询

数据库可以包含多张表。表用行和列组织数据，每一行表示一条记录，每一列表示一个属性。本例使用 `concert_singer` 数据库中的 `singer` 表，表名可以理解为“歌手”。

该表实际包含七列，第一课先查看姓名、国家和年龄三列。以下六行来自本地数据库，已执行标准 SQL 验证。

| Name，姓名 | Country，国家 | Age，年龄 |
| --- | --- | ---: |
| Joe Sharp | Netherlands | 52 |
| John Nizinik | France | 43 |
| Rose White | France | 41 |
| Timbaland | United States | 32 |
| Justin Brown | France | 29 |
| Tribal King | France | 25 |

真实样本要求可以译为“列出每位歌手的姓名、国家和年龄，按年龄从大到小排序”。对应的标准 SQL 如下。

```sql
SELECT name, country, age
FROM singer
ORDER BY age DESC;
```

- `SELECT name, country, age` 选择结果中要显示的三列。
- `FROM singer` 指定从 `singer` 表读取数据。
- `ORDER BY age` 按年龄排列结果。
- `DESC` 表示降序，年龄从大到小。`ASC` 表示升序，年龄从小到大。

SQL 是向数据库表达查询要求的语言。这里通过查询选出需要的列并排列结果。

## 从查询过渡到 Text-to-SQL

Text-to-SQL 模型需要接收自然语言问题和表结构等信息，生成对应 SQL。样本中的几个字段含义如下。

| 字段 | 本例含义 |
| --- | --- |
| `db_id` | 使用 `concert_singer` 数据库 |
| `question` | 自然语言提问 |
| `query` | 数据集提供的标准 SQL，后续用来评测预测 |
| `q_id_spider_dev` | 对应到原始 Spider-dev 问题的标识 |

实际让模型预测时，将问题与允许使用的数据库信息交给模型，再把生成结果与标准答案按评测协议比较。

本例来自 `NLQ_keyword_synonym` 子集的第 1 对样本。扰动后的问题可以译为“给出每位歌手的姓名、国家和年龄，从最年长的开始”。两种说法指向相同查询，因此这对样本的标准 SQL 相同。

`SQL_sort_order` 的第 1 对样本则把“从年长到年轻”改成“从年轻到年长”，标准 SQL 中的 `DESC` 随之变成 `ASC`。后续将通过这一对比理解语义保持和语义改变两种扰动。

## 至少五类问题的学习起点

以下依据官方扰动类别和已读取的真实样本，作为后续分类分析的起点。模型在这些类别中的实际表现需要运行基线后测量。

| 类别 | 已读取样本中的变化 | 后续观察的问题 |
| --- | --- | --- |
| 表结构同义改名 | `Country` 变成 `nation` | 模型能否根据新列名找到国家列 |
| 表结构缩写 | `Country` 变成 `cntry` | 模型能否识别缩写 |
| 问题关键词改写 | 降序表达改写为“从最年长开始” | 模型能否保持排序含义 |
| 问题列名同义表达 | 场馆容量的表达由 capacity 改成 size | 模型能否对应到正确列 |
| 排序方向改变 | 年龄降序改成升序，`DESC` 变成 `ASC` | 模型能否随着需求调整 SQL |
