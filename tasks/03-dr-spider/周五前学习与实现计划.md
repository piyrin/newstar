## 本周范围的建议

以下为结合 12 小时投入提出的实现范围，可按老师要求修订。

**数据实验。** 选择表结构同义改名、表结构缩写、问题关键词改写、问题列名同义表达、排序方向改变五类。每类先用一对样本跑通完整链路，随后每类固定抽取五对，共 25 对、50 次预测。固定抽样种子并保留原始样本标识，正式结果按完整清单统计。样本规模属于本周抽样实验安排，解释结论时说明样本范围与局限。

**基线。** 使用一个模型，根据问题和允许使用的数据库信息直接生成 SQL。优先检查现有本地模型及适配器是否可用，记录真实模型名、版本、提示词、采样参数、输入与原始输出。云端调用的服务与费用需结合用户授权确定。第一批试跑测量平均耗时，据此安排后续批次。

**Agent。** 复用同一个模型适配器、SQLite 读取与结果记录逻辑。单表 Agent 具有表结构读取和只读查询工具；协作阶段让表 Agent 根据当前问题返回字段、键和必要信息，协调 Agent 根据真实消息生成 SQL。执行失败时最多修订一次，保存每一步输入输出。

**界面集成。** 优先复用项目现有输入框、结果区和调用方式。周一明确接入位置，周三完成单表能力接入，周四在相同入口完成协作案例。

EX 为执行准确率，按正确样本数除以该侧样本总数计算。变化采用扰动后减扰动前，以百分点报告。评测优先使用官方链接的评测实现，并记录版本与参数。指标名称应对应实际采用的数据库与评测口径，单库执行一致率和 test-suite accuracy 的配置分别写清楚。[Dr.Spider 使用说明](https://github.com/awslabs/diagnostic-robustness-text-to-sql/blob/main/README.md) [评测项目](https://github.com/taoyds/test-suite-sql-eval)

每类仅五对样本时，一对样本就对应 20 个百分点。报告中应说明这是固定样本的初步实验，附上逐条结果，后续有余量再扩大每类样本数。

五种扰动对应五类待诊断困难，后续再根据真实预测统计模型错误。某一类实际全部通过时，如实报告通过数，并分析已覆盖的条件。
