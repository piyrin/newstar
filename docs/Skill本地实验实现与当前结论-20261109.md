## 如何实现

1. **建立真实来源库。** registry记录名称、原始description、SKILL.md路径、来源及SHA-256。增加N时使用嵌套候选集，原有候选保留；每次试验完整保存该集合与任务资料。
2. **模型自主选择与组合。** 本地所有N个候选的名称、原始说明及参数同时进入规划器；不先检索缩小集合。被选择后，工人加载其完整原始SKILL.md、原始facts和真正被引用的上游正文。没有预设业务DAG。
3. **本地执行。** 使用电脑已有Ollama与Qwen3.5:9b；HTTP仅允许loopback，不读取付费API凭证，没有云端回退。当前能力范围是原文驱动的文本、文档和模板生成；没有声称为每个第三方服务建立了原生连接。
4. **真实保存与依赖。** 工人正文落成Markdown，代码块/CSV导出成真实附件，校验哈希后返回DOC/FILE引用。下游只能引用实际存在的ID；修订生成新ID。根据实际上游计算DAG边、节点深度和最长链。工具拒绝或无效调用不生成成功节点。
5. **在同一预算内审阅修订。** 最多16轮规划，含审阅、修订及正式提交。read_artifacts、review_deliverables与submit_deliverables是三个控制工具，单列，不计业务Skill。最终清单必须对应一次已经通过审阅的真实引用集合，提交后仍有独立终验。
6. **验证真正的结果。** 校验实体/哈希、CSV语法与列数、指定字段和命令；活动任务从实际文档行号取证，Python核验人数、时长、窗口、重叠和预算。语义验收在隔离上下文逐项核对原要求。离线audit再核对原文加载、上游内容、真实DAG、最终引用及晋级门槛。

## 规模和成功率

- **N：候选Skill数。** 审阅/提交等控制工具另列。
- **K：实际成功使用的不同Skill数。** 同一Skill调用多次只增加节点，不增加K。
- **DAG节点数：** 真正产生落盘产物的业务调用数；失败尝试另报。
- **链长：** 按真实上游边计算的最长路径节点数，不是总节点数。
- **端到端观测成功率：** 通过试次/已结束的全部试次，含上下文截断失败；未执行另列，不能冒称已经完整测试。本次140和163的分母均为4，不剔除失败后再报100%。
- **完整任务族晋级：** 同一配置下六类原任务各两次，完整12/12才进入下一档。当前固定单例扫描另列，失败计0后可独立观察更高候选规模；不把一次失败当硬上限。通过样例不跨配置拼接。
