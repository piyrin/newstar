# 多 Skill 扩容实验与实现说明

> **口径纠正：本记录仅是预设角色、固定DAG下的候选目录路由试验，不构成本次作业要求的Skill编排上限证据。撤回据此与老师实验室“100多个”的结果作比较的结论。** 原始数据保留；已核对的偏差及重新对齐方案见 [实验口径审计](skillfabri-实验口径审计-20261108.md)。2207仅是文档注册数，尚非2207个已按原能力验证可调用的Skill。

2026-11-08，北京时间。本轮按用户“越多越好、超过100个，并说明实现”的要求继续接入试验。未修改现有简历流程，未提交或推送。

## 实际规模与结论

- 下载新增来源包 **2200** 个，加上前轮8个，按同名或规范化文档内容哈希去重排除1个，注册表为 **2207** 个。
- 2207个名称、规范化文档哈希均各不相同。SKILL.md总计20,171,898字节；这是精确内容去重，不代表不存在功能重叠。
- 候选选择压力测试：8、32、64、128、256、512、1024、2048，每级3轮，共24轮。
- 完整工作流：8、128、512、2048，每级3轮，共12轮。
- 每轮需求和逻辑DAG固定，**实际选择并调用8个不同Skill，DAG为10个节点，最长依赖链为8个节点（7条边）**。候选库扩大不自动增加DAG节点数。
- 模型deepseek-flash，temperature=0.2，无自动重试；固定虚构竞赛材料，候选顺序按三个种子打乱。角色预设，拓扑固定，尚未测试任意需求下自动生成任意DAG。

本试验没有测量出可与老师实验室结果比较的Skill编排上限。2048表示该弱化试验的候选目录规模；由于编排预设、调用适配和判据均未对齐，不能用其支持或否定“100多个”的实验结果。

## 测量结果

“选择有效”只要求返回所有角色的合法注册ID；“完整验收”要求结构化产物及当前业务检查通过。两者不能混为一个成功率。

| 候选Skill数 | 选择有效轮数 | 完整工作流自动验收通过 | 选择阶段输入token（约） |
|---:|---:|---:|---:|
| 8 | 3/3 | 2/3 | 926 |
| 32 | 3/3 | 未测 | 2119 |
| 64 | 3/3 | 未测 | 3575 |
| 128 | 3/3 | 3/3 | 6364 |
| 256 | 3/3 | 未测 | 12783 |
| 512 | 3/3 | 3/3 | 24664 |
| 1024 | 2/3 | 未测 | 48730 |
| 2048 | 3/3 | 3/3 | 97355 |

每格只有三轮，属于试运行比例，不是一般稳定率估计。8个候选基线失败而更大规模通过，不能据此得出增加候选提升成功率，也不能用单次失败定义上限。

失败证据：

1. `scale/routing/scale-a-n1024-t3/response.json`：模型返回未注册ID `aas:brainstorming`，对应原有能力的注册ID是 `core:brainstorming`。属于标识符选择错误；不能笼统说模型不知道头脑风暴能力。
2. `runs/scale-b-n8-t2/stories.output.json`：要求故事使用 `id`，模型却使用 `story_id`，最终验证在读取 `id` 时失败。说明固定字段协议本身也会不稳定，与大候选库无直接因果证据。

等效Skill证据：

- 512候选的 `scale-b-n512-t1` 实际选用 brainstorming 做情境分析，product-design-harness 做方案探索；`t3` 选用 customer-research。当前结构和业务检查均通过。
- 2048候选的三轮均选用新增的 jobs-to-be-done-analyst 替代原 job-stories，完整自动检查通过。
- 因而“必须选回原先八个标准名字”的完全一致率只能作为参考，不能直接作为正确率。本轮同时保留该指标原始数据，未把合理替代全部判错。

## 如何实现

### 1. 来源发现与固定版本

前轮从老师的 [SkillFabri](https://skillfabri.com) 获取公开目录及原作者链接。本轮沿其收录的来源仓库 sickn33/antigravity-awesome-skills 扩容，固定提交：

`828257c3037dc7c3c3ec987decc5a603025a0ce5`

读取文件树，只取根目录 `skills/` 下的包，排除插件镜像路径；按与产品、规划、数据、测试等相关关键词排序，取2200个包。此次新增包来自该来源仓库的固定版本，不宣称每个包都是SkillFabri目录中的独立条目。

调用官方 skill-installer 的Python入口，一次下载仓库再安装多个指定路径，避免2200次重复下载。没有执行下载包里的第三方脚本，也没有修改全局Skill目录。

### 2. 注册表

每个条目记录：

```json
{
  "id": "aas:jobs-to-be-done-analyst",
  "name": "jobs-to-be-done-analyst",
  "description": "从原SKILL.md提取的描述",
  "path": "本地SKILL.md绝对路径",
  "source_url": "固定提交的来源链接",
  "sha256": "原始文件摘要",
  "normalized_sha256": "规范化空白后的文档摘要"
}
```

名称重复或规范化内容摘要重复时排除。原8个核心条目使用 `core:` 命名空间，新条目使用 `aas:`，避免同名来源冲突。每个大规模候选集合保留核心8个，再按同一顺序逐级增加条目；各轮仅打乱展示顺序。

### 3. 模型选择Skill

选择阶段发送：用户需求、8个角色说明、每个候选的唯一ID和最多320字符描述。角色包括用户情境、方案、用户故事、MVP、计划、测试、数据、SQL。

模型返回JSON映射：

```json
{
  "bindings": {
    "jobs": "aas:jobs-to-be-done-analyst",
    "design": "core:brainstorming",
    "stories": "core:user-stories"
  }
}
```

程序检查角色是否齐全、ID是否真的在本轮候选中。不会把拼错的ID自动当作成功。当前直接展示全部候选元数据，未使用向量检索、分层检索或top-k预筛选。

### 4. 按需读取完整Skill并执行

模型选中某个ID后，程序从注册表找到对应SKILL.md，读取完整正文，将其作为当前任务的方法参考，再发送当前节点任务、统一输出契约、业务约束和直接上游产物。

因此：候选目录可能有2048项，真正进入单个执行请求的完整Skill文档只有该节点选中的一份。

这批Skill通过 **SKILL.md提示词适配器** 使用。它们没有全部被原生激活成Codex插件，包内命令、脚本、浏览器动作和第三方工具接口也没有逐一实现。程序实际执行的额外操作是本地SQLite只读查询及确定性校验。

```mermaid
flowchart LR
    A[自然语言需求] --> B[候选Skill目录]
    B --> C[DeepSeek选择合法ID]
    C --> D[读取选中的完整SKILL.md]
    D --> E[节点任务与上游产物]
    E --> F[DeepSeek生成结构化产物]
    F --> G[依赖图下游节点]
    G --> H[本地确定性校验]
    H --> I[结果、失败位置与原始证据]
```

### 5. 依赖执行与验证

逻辑DAG：路由→用户情境→方案→用户故事；用户故事分到MVP和样例数据；MVP分到计划和测试；数据、测试汇入SQL；最后统一验收。共10个节点，最长链8个节点。

当前按拓扑顺序执行；单轮未并行独立节点，三轮试验之间最多3路并行。某节点失败，依赖它的下游标记blocked，独立分支仍可继续。未部署到Airflow。

检查包括：节点身份、约束传播、通知ID覆盖、七天闭区间选择、六条原样数据及缺失日期null、故事ID及验收条件、测试覆盖、计划/MVP引用、预算人数工期，以及SQL实际查询结果。明确数据节点只允许id/title/deadline三列，减少前轮出现的额外字段问题。

SQL参考结果为C1、C3、C6；SQLite启用只读与执行步数限制。自动检查验证的是这些明确的协议和业务属性，尚未逐句审阅全部产物，也不代表产品价值与可用性已获用户验收。

## 代码与原始证据

路径均以 `D:/code/newstar/tmp/skillfabri-spike/` 为基准：

| 文件 | 用途 |
|---|---|
| expand_library.py | 批量安装、固定来源、解析描述、去重建库 |

代码和大体积Skill包位于已有gitignore覆盖的临时目录。需要长期保存、迁移或提交时，应把运行器整理为正式实验模块，并单独管理来源清单和大体积依赖。

复现时在项目根目录执行，使用不同prefix避免覆盖证据，复用已配置的本机DeepSeek密钥：

```powershell
python tmp/skillfabri-spike/scale_benchmark.py --prefix rerun-a --mode routing --sizes 8 32 64 128 256 512 1024 2048 --trials 3
python tmp/skillfabri-spike/scale_benchmark.py --prefix rerun-b --mode execution --sizes 8 128 512 2048 --trials 3
```

## 当前能汇报的研究结论

这些数据可以作为前期目录路由与适配器调试记录。不得将2207个文档注册或2048候选路由表述为作业要求下已验证的可调用Skill规模、编排上限，或用来否定老师实验室结果。正式报告须使用重新对齐调用能力、模型编排责任、任务覆盖和验收判据后的运行证据。
