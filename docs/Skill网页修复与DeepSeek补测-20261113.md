## DeepSeek 数量边界的理论讨论

2026年11月13日查阅官方文档，`deepseek-flash` 对应 DeepSeek-V4.1-Flash-1017，上下文为1M。Chat Completions 文档要求工具名称唯一，本次阅读的接口文档没有给出工具数组的数量上限。实际供应端行为仍需请求验证。[模型说明](https://api-docs.deepseek.com/quick_start/pricing/) [Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/)

当前同一需求的首规划请求实测 N100 输入17627 tokens，N180 输入30217 tokens，分别包含103和183个接口。两点线性外推得到每新增候选约157.4 tokens，固定部分约1890.5 tokens。两组描述长度分布有差异，该斜率仅供当前注册方式的局部估计。

若预留约2万至5万 tokens 给历史、工具读取和输出，按1048576上下文计算，静态目录的容量外推约为6300至6500个候选。考虑来源描述分布和后续历史增长，约5000至6500可以作为未来容量探测范围。该范围属于输入容量估计，尚未测量这些规模的真实不同 Skill 库。

稳定失败数量还受相似候选的选择干扰、选中源全文长度、修订次数、16轮预算和事实错误影响。单一上下文容量无法推出业务稳定失败点。当前可用且已有资格证据的真实候选库为180，本轮100与180各十次用于验证现有库范围内的正确性与失败机制。稳定失败临界数量仍需进一步扩库及重复实验。
