# Skill数量边界实验 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. User has authorized continuous execution; no approval handoff, no delegation, no commits or paid API calls.

**Goal:** 补齐挑战档所需的边界附近系统探索、成功与失败复现、原因对照和可审查的正确性证据。

**Spec:** 用户本轮目标及其选中的挑战档缺口；沿用LOCAL_PROTOCOL.md与现有C组任务/验收。

**Architecture:** 保留原163候选顺序和全部原始记录，新增可追溯来源并先做本地原能力功能测试；独立新系列扩大候选池。粗测定位退化区间后加密重复，另外冻结相同模型输入做上下文对照，区分资源截断与业务/路由失败。

**Tech Stack:** Python标准库、现有Ollama/Qwen3.5:9b，本地HTTP；所有文件在本工作区。

## Global Constraints

- 禁止付费API、读取云端凭证、安装虚构/复制改名Skill凑数。
- N候选、K实际种类、真实DAG节点/链长和端到端成功率分别报告。
- 原任务、16轮预算、全部候选说明同时曝光、严格全部CSV检查和独立终验不降低；变更配置另组。
- 失败、截断、未完成全部保留；无裁剪成功，不将注册数当验证可调用数。
- 结果只作指定模型/任务/加载方式下的条件性边界，不虚构普遍上限。

## Review Focus

1. 来源重复或改名：原始/归一化哈希与名称双去重。
2. 必需工具缺失：依赖性Skill不能用泛化方案冒充执行成功。
3. 不完整/截断回复：明确失败，保存原响应及日志片段。
4. 换配置拼接成功率：冻结协议与精确请求，分组报告。
5. 预期门槛误判：程序硬检查与逐文核查并列，测试替身不算实测。
