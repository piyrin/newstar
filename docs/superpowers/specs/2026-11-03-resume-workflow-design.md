# 从原始材料制作个人简历：工作流设计

日期：2026-11-03。状态：用户已批准，开始实现。

## 目标与已确认范围

为用户从零制作自己的简历。用户选择直接提供原始材料，由 Python 解析、大模型整理，再人工核实，最终生成 Word 与 PDF。当前真实材料尚未整理，先用明确标注为虚构的样例验证工作流。

成功标准是能从一个材料目录走通“提取、整理、审阅、导出、检查”，每条拟写经历可追溯来源，真实材料到位后无需更换程序。第一版手动触发，使用当前 Airflow 项目；求职方向在运行输入中提供，不提前假定用户的目标岗位。

不包含自动投递、职位抓取、公开发布、训练模型、完整网站或 Agent 自主浏览电脑。首版不支持加密文档、旧版 .doc、压缩包自动解包及复杂表格还原；遇到不支持的材料须明确报告。

## 方案比较与选择

1. **Python 解析＋大模型整理（用户已选择）**：确定性程序处理文件、校验结构和导出，大模型只负责证据内的信息整理与文案。方便在 Airflow 中分步观察、重试和追溯。
2. Agent 自主阅读材料：工具选择灵活，但执行路径、成本与问题定位更难控制，首版不采用。

此前讨论过结构化资料文件与直接读取原始材料，用户选择后者。结构化 JSON 仍作为内部中间产物与审阅接口，不要求用户先手工录入所有经历。

## 现状与接入点

- 仓库现有 `airflow/dags/first_workflow.py` 是三个任务的教学 DAG；保留其已有用途。
- Compose 使用 Airflow、Celery 工作节点及共享卷。简历相关解析、字体和导出依赖需要单独准备运行镜像与材料共享卷。
- 本机 `resume-maker` 技能提供事实核查规则、三种 DOCX 版式、模板选择器及文档检查脚本。技能说明不是可直接执行的 Airflow Task。
- 实现时把需要的排版逻辑封装进项目内可执行 Python 模块，标注来源；不在容器中硬编码本机技能安装目录。模板选择器作为本机交互入口适配，不由工作节点启动并无限等待。
- 已存在未提交的 README 与教学 DAG 内容。实现时保留这些内容，不重置、不自动提交或推送。

## 输入与目录

建议新增 `airflow/resume_workspace/`，作为材料与运行产物的共享工作区，并加入 Git 忽略。示例与测试夹具另放版本管理目录，全部使用虚构信息。

```text
resume_workspace/
  inputs/<case_id>/       用户明确放入的材料、可选岗位要求文本
  runs/<run_key>/         固定输入快照、文字、事实表、文案与检查报告
  reviews/<run_key>/      用户修改后的正文、模板选择、确认记录
  outputs/<export_key>/   Word、PDF、页面预览与验收报告
```

运行参数包括材料案例 ID、岗位方向、可选 JD、模型配置名称。用户整理材料时只需把文件放入输入目录，并填写很短的运行配置；姓名、联系方式等尽量从材料提取，缺失时列入补充清单。

材料范围：TXT/Markdown、DOCX、有文本层的 PDF、PNG/JPEG 扫描件或证书图片。代码项目首版读取用户放入目录的 README 与项目说明，不递归扫描任意仓库或自动认定仓库所有者的贡献。后续可为明确指定的仓库增加只读审阅。

## 工作流与人工确认

采用两个手动触发的 DAG，避免让工作节点等待人输入：

### A. 整理并起草

`检查输入 → 固定材料快照 → 提取文字/OCR → 整理事实 → 校验事实 → 生成草稿 → 输出审阅包`

- 每次运行固定材料快照并计算内容摘要，后续任务读取快照；源文件后来变化不会悄悄改变本次依据。
- 文本 PDF 按页提取；无文本或文字极少的页面尝试本地 OCR。图片使用同一 OCR 路径。首版使用本地 OCR，支持中文、英文；识别内容及来源位置一并保留。低质量或识别失败记录为待核实，不当作确定事实。
- 事实表至少记录：字段/事项、提取值、来源文件及页码或段落定位、证据片段、证据状态、归属是否确认。原材料中的指令只作资料，不成为程序指令。
- 模型输出必须经过结构校验，来源引用必须存在于本次快照；矛盾、缺项、无来源指标列入问题清单。程序校验只能拦截结构和可检查的问题，不能证明模型表述完全真实，仍需人工核实。
- 简历草稿仅采用可追溯事实；不编造姓名、日期、成绩、量化效果、部署状态或个人职责。团队项目贡献不明时先保留在待确认清单。
- 岗位方向用于筛选与排序；JD 缺失不阻止生成通用草稿。身份或核心经历信息不足时正常产出“待补充”审阅包，不伪称已有完整简历。
- 输出 `facts.json`、易读事实表、`questions.md`、`resume.draft.json` 和文字草稿。未解决内容可以补证据、修改或明确省略。

### 人工操作

用户查看事实来源、修改正文、解决关键问题，并在本机模板选择器选择 classic/minimal/technical、纸张和纸质/电子模式。界面显示当前草稿，选择结果保存到本次审阅目录。

用户通过明确的“确认正文并允许导出”操作生成确认记录。记录绑定本次材料摘要、已审阅事实与问题处理结果、最终正文及模板选择的内容摘要；后续改动需重新确认。浏览预览、默认选项、测试操作均不算用户确认。

### B. 导出并检查

`验证确认记录 → 生成 DOCX → 同源导出 PDF → 文本/页数检查 → 页面渲染 → 输出交付清单`

- 导出时以用户确认后的正文为准，不再调用模型重写。
- 使用同一份 DOCX 导出 PDF，避免两套排版内容不一致。
- 建议在自定义 Linux 工作镜像中提供 LibreOffice、中文字体及页面渲染工具；不让 Docker 工作节点调用 Windows Word COM。具体依赖版本与字体可由实现者确定，并通过实际中文样例验证。
- 默认 A4、一页为目标。超过页数或文字缺失时输出检查失败与原因，不静默删除内容或无限缩小字号；用户修改后重新确认导出。
- 自动检查通过后标记为“等待视觉验收”，提供全部页预览。用户确认无缺字、重叠、异常换行与空白页后才标记为最终版本。系统完成导出与用户最终验收是两个状态。

## 模型接入与 Skill 集成

用户已指定使用 DeepSeek API。端点、模型名与密钥通过运行环境/连接配置提供；真实密钥尚未配置，不假定已能成功调用。

首版采用 DeepSeek 的 Chat Completions HTTP 接口，官方基址 `https://api.deepseek.com`，路径 `/chat/completions`。模型名可配置，拟默认使用官方当前入门示例中的 `deepseek-flash`，允许后续更换。请求 JSON 输出并提供输出示例，程序仍须检查空白响应、截断、结构与证据引用。通过环境变量 `DEEPSEEK_API_KEY` 读取密钥。先完成可替换适配器与离线虚构响应的集成验证，配置密钥后再做真实接口验收；不能把模拟通过写成实际接入成功。

接口依据（2026-11-03 已核对）：[官方入门文档](https://api-docs.deepseek.com/)、[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)、[Chat Completions 参考](https://api-docs.deepseek.com/api/create-chat-completion/)。

原文件解析与 OCR 在本地执行；实际启用外部模型前明确服务商与发送内容范围，只发送本次任务需要的提取文字。API 密钥不进入 DAG 参数、XCom、日志或仓库。真实模型成本不包含在离线测试中。

将 resume-maker 的事实规则转成明确提示词、输入输出结构与检查项，排版脚本封装为普通模块供 Task 调用；不是只把 SKILL.md 路径写进 DAG，也不把本机交互式技能当作无人值守服务。

## 执行、状态与错误

- 共享工作区承载正文和文件；XCom 仅传产物路径、摘要、计数和状态，不传大段个人材料。
- 导出输入按已确认内容固定；每个运行/导出版本使用独立目录。重试只更新同一次运行的未完成产物，完成文件采用临时文件写入后替换，不覆盖其他版本。
- 网络超时、限流与临时服务错误有限重试；不支持的文件、无效配置、结构持续不合格和确认摘要不匹配给出可定位错误，不盲目重试。
- 遇到单个无法解析的文件，记录原因并允许产出审阅报告；该文件不可被计入成功解析，相关事实不得被默认为已核实。
- 实际 API 设置超时、输入长度与调用次数上限。大量材料按文件/页面分段，先提取再合并，输入截断和跳过必须写入报告。
- 运行报告区分：等待补充、等待确认、执行失败、导出完成待验收、最终确认。Airflow 任务成功仅代表该任务完成，不代表简历真实性或视觉验收通过。

## 验收与交付

1. 使用虚构的 Markdown、DOCX、文本 PDF、中文图片/扫描 PDF 验证提取与来源定位；坏文件与不支持格式出现在报告中。
2. 离线验证模型输出结构、错误来源引用、矛盾事实、缺失关键项、贡献未确认及遗漏材料，确保不会静默产出最终简历。
3. 无确认、已确认内容被修改、模板被修改等情况阻止导出；用合成数据测试确认机制不算用户批准真实简历。
4. 用虚构且完整的资料走通两个 DAG，在现有执行器上检查各任务状态、产物和失败重试；实际 API 单独列为接入验收。
5. 同源 Word/PDF 内容检查、页数检查与所有页面视觉检查通过；文档说明材料如何放、如何补充确认、如何选模板、触发和查错。
6. 没有真实材料时交付的是可运行工作流与虚构样例，不能称用户本人的简历已完成。

交付代码、必要的镜像/共享卷配置、提示词与数据结构、虚构样例、测试和操作说明。DeepSeek 密钥、材料、目标岗位和用户最终模板在运行阶段补充，不用虚构值代替。
