# 增量简历制作与自然语言触发

用户要求：定时检查，有更新才制作，相同材料已完成则跳过；补全任务 3。

沿用现有 Python、DeepSeek、Airflow 两阶段流程。选择在 resume_prepare 首任务增加内容判重并为该 DAG 配置半小时检查；相比另建轮询服务或让模型生成任意代码，现有调度和日志可直接复用。resume_export 继续手动调用并验证人工确认。

比较路径、内容摘要、目标岗位、JD、模型模式及流程版本。扫描固定快照，使用确定性版本标识；首次成功发布审阅包后才写完成记录。无变化的已完成版本跳过下游；失败版本重用快照继续执行；文件新增、删除、改名或内容变化产生新版本。只改变修改时间不重复制作。显式 run_key 保持旧的版本隔离约定。默认每半小时检查 demo，DAG 初次创建暂停；通过环境变量指定自动检查的案例和岗位，手动参数可覆盖。

任务 3 提供 CLI ask/chat：自然语言由真实 DeepSeek 解析为 prepare/export/status/clarify JSON；程序验证动作、字段、现有材料及审阅版本，再调用 Airflow 3 JWT + /api/v2。只允许两个已有 DAG；导出无法代替人工确认。模型不接收密钥和材料正文，仅接收请求与案例/运行标识。提供 dry-run、请求 ID 防重复提交、运行状态和任务状态查询。接口或模型错误明确报错，不伪装成功。

验收：相同内容跳过；内容与配置变化重做；失败后重试；旧审阅不覆盖；无确认拒绝导出；模型非法动作拒绝；REST 认证、触发、冲突复用和状态链路测试；真实环境可用时做真实 DAG/API 验证，否则明确记录缺口。
