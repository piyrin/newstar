## 五个数分别是什么

|指标|统计口径|例子：E40 N100/seed3 的正确试次|
|---|---|---:|
|N|同一规划请求可见的不同业务 Skill 候选数|100|
|K|本试次真正生成产物的不同 Skill 种类|3|
|业务 DAG 节点数|实际生成并落盘产物的业务调用数|3|
|最长依赖链|真实依赖路径上的节点数；根深度为 1|2 节点，即 1 条边|
|端到端内容通过率|同配置完整通过数 / 全部已完成试次|该档 1/3|

该试次使用 project-brief 生成发布材料，developer-onboarding、knowledge-base 分别读取其真实产物生成后续文档。具体 Skill 和依赖由模型决定。read_artifacts、review_deliverables、submit_deliverables 是三个控制工具，另列，不计入 N、K 或业务节点。

失败试次也可能产生多个真实节点；这些节点不能称为“正确有效步骤”。单个 Skill 重复三次会增加节点数，不会使 K 变成 3。

## 如何接入和编排

1. **固定来源。** 从老师给出的 SkillFabri 查到公开来源，保存原 SKILL.md、原始说明、来源版本和 SHA-256。当前工作库为 166 项；其中原 163 项保留历史资格，本次新增 3 项各通过三个不同 seed 和一次相同 seed 重跑，全部 4/4 内容正确。另三个新增候选未过门槛，原记录保留。
2. **注册统一调用接口。** 每个真实来源对应一个业务工具，参数为自然语言子任务和上游引用 ID。它是原文驱动的本地文本/文档执行适配，不能声称所有第三方账号、云 API 或原作者脚本均已接通。
3. **同时展示所有候选。** 本轮 on-call 模式将 N 个原始名称、说明及接口同时交给规划器；没有先检索成少量候选。选中后，工人读取完整原 SKILL.md、全部原 facts 和模型明确引用的完整上游正文。没有将全部 N 份原文同时塞入规划上下文；这种曝光方法必须在汇报中说明。
4. **模型决定流程。** 规划器自主选 Skill、拆任务和传依赖。没有固定八角色或预写 DAG。每次业务调用的原始输出直接落盘为 Markdown，CSV 等代码块导出真实文件；主机不代写或修补业务答案。
5. **用真实引用传递产物。** 生成 DOC/FILE 不可变 ID；下游只能引用实际存在的 ID，修订创建新 ID。依赖边和链长由实际引用计算。规划器默认看到长度、哈希等回执；显式读取可获得完整正文，业务工人和审阅仍读取完整相关正文。
6. **在同一预算内纠错。** 每次最多 16 轮规划，读取、审阅、修订和提交都占用原预算。先审阅候选最终清单；通过后才能正式提交同一引用集合，随后仍需隔离终验。无隐藏重试、抽掉失败或补写成功答案。

原始“注册 2207、固定角色路由到 2048”试验已经撤回作为本题编排上限的证据。文件注册数不能替代真实能力和正确运行证据。

## 正确与失败如何判断

任务为一个虚构开源项目的完整发布材料包，包含功能/限制、给定命令的新手说明、规定字段顺序的空 CSV，以及明确标为建议的反馈流转和维护职责。六项标准是功能/版本/许可准确、两条命令准确、实际空 CSV 正确、未知不编造、方案可用且标为建议、最终材料一致。

程序检查真实文件、哈希、CSV 列数/字段/空记录、命令、引用和依赖；隔离的本地模型逐项给出真实文档行证据。原自动正例再由 Codex 主代理阅读全文和实际附件复核，错误就追加否决记录，不修改原分数。这不是教师或另一独立研究者的验收。

两个明确失败例：

- E40 N100/seed2 把 Skill 的作者 WHOISABHISHEKADHIKARI 当成 CourseDock 所有者；原项目资料没有提供负责人。
- E40 N166/seed3 写出 `pip install coursedock`、无 Web 界面、仅支持 CLI；安装命令和这些界面信息在输入中均为未知。

这些是语义失败，不能解释为“100 或 166 个工具就是模型硬上限”。E32 的部分试次发生超过 32768 的完整输入拒绝，属于上下文资源失败，另行记录；服务器明确禁止 truncate/shift，不接受静默裁剪后的偶然成功。

## F 版正在验证什么

F 与 E 分目录、分协议、分校准和分结果。F 保留原任务、全部事实和六项标准、候选顺序、完整源/上游、16 轮预算及本地模型，仅有两类模型输入改进：

- 模型可见的存储路径改成基于真实不可变 ID 的 `artifact://DOC-...` / `artifact://FILE-...`，包括审阅错误反馈；实际物理文件和取证路径保留。这消除不同运行目录带来的额外输入变量，不保证 GPU 位级确定性。
- 在完整源 Skill 后追加通用来源边界：作者/来源仓库不等于目标项目事实，null 表示未知，不能补造界面、安装或网络行为。主机不修改模型返回的业务正文。

五项新增离线回归在旧 E 上失败，F 全部 120 项通过；它们证明接口、内容保留及实际消息传输，**不算业务成功**。F32 独立校准六个已知标签匹配，其中五个规则拒绝、一个模型接受，不是六次模型语义判断全部正确。F32 两档六次已全部结束：N100 自动 3/3、内容复核 1/3，仅 seed2 正确（K3/节点4/最长链4节点，含预算内修订）；N166 自动 2/3、内容复核 1/3，仅 seed3 正确（K2/节点2/最长链2节点，product-design-harness→copy-editing）。166 另两次分别因完整输入超限、无依据的网络/UI断言失败。F32 的 N100 与 E32 正确率相同，成功 seed 不同；没有证明总体稳定性提高。F40 两档也已完成，N100/N166 三次内容复核均为 1/3。F32/F40 的 N100 三个 seed 共37个请求逐项仅上下文长度不同，最终正文哈希及正确向量相同；不把不同上下文合并成功率。原 F32 N166/seed3 已按预注册在新目录真实重跑，原完整任务再次正确完成（K2/节点2/链2节点）。新终稿89行、原稿85行，功能结果复现，逐字轨迹没有复现；初始planner和首worker请求字节相同，首worker生成正文却不同，具体运行时原因未隔离。该已知seed复现不新增独立样本，不改变原1/3正确率。
